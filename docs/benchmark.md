## 三方定位

- **New API**：完整 SaaS 网关——多租户计费（电子钱包、订阅、`expr` 阶梯计费、工具计费）、
  社交 OAuth 登录、充值支付（EPay/Stripe/Waffo）、Midjourney/Realtime/Rerank。终局形态
  参照物，但其商业化面不在本产品范围。
- **All API Hub**：本地优先的"AI 资产管家"——聚合多站余额/用量/签到/价格对比/公告，
  一键分发客户端配置，远程管理 New API 系网关渠道。**不转发流量**，价值在"省事"。
- **MetAPI-Go**：服务端聚合网关——真实转发 + 智能路由（权重/冷却/熔断/重试）+ 多平台
  账号聚合 + 运维审计。三者中唯一做真实流量转发的，价值在"可用性与省钱"。

## 核心结论

**MetAPI-Go 在"转发 + 路由 + 运维"三角已三方最强；最大产品缺口在"分发端"；商业化
与多租户明确不做。**

三条关键用户动线：

1. **接入动线**：All API Hub 4 步零手抄（捕获 → 测试 → 导出）；MetAPI-Go 6 步且最后
   一步（复制 baseURL/key 手填客户端）靠手抄。缺口 = 客户端一键导出 + 接入向导。
2. **巡检动线**：MetAPI-Go 的告警 + 每日摘要已比对手主动；缺一张首页"今日快照"
   （签到/余额/告警/可用性一屏聚合）。
3. **故障动线**：告警 → observability → fix-candidates 闭环已是三者最完整；可增强告警
   消息带上下文（受影响路由 + 替代站点 + 直达链接）。

## 路线图（P0 / P1 / P2）

- **P0 分发端**（对标 All API Hub 护城河）：
  1. 客户端配置一键导出（Cherry Studio / CC Switch / CLIProxyAPI / Claude Code Router）。
  2. 接入向导：平台 → 凭证（URL 自动识别）→ 连通性测试 → 引导建 token 路由。
- **P1 管理体验**：
  3. 全局搜索（跨站点/账号/模型/路由/告警，对手均无，可超车）。
  4. 首页今日快照。
  5. 价格对比增强：路由实际分配权重 vs 各站价格对照。
  6. 告警富化：受影响路由 + 替代站点 + 直达链接。
  7. 测试台增强：模板库 + 批量延迟对比。
- **P2 生态**（需需求信号）：WebDAV 加密同步 · 移动端 PWA · Realtime/Rerank 转发。

## 明确不做（定位边界）

- 多租户计费 / 钱包 / 订阅 / 支付——组合优于重造，真需要时前置 New API 实例
  （MetAPI-Go 本来就是它的上游聚合器）。
- Electron 桌面版、社交 OAuth 登录。
- 多实例 sticky 共享改造（当前诚实标注 single-instance）。
