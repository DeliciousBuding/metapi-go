## 三方定位

- **New API**：完整 SaaS 网关——多租户计费（电子钱包、订阅、`expr` 阶梯计费、工具计费）、
  社交 OAuth 登录、充值支付（EPay/Stripe/Waffo）、Midjourney/Realtime/Rerank。终局形态
  参照物，但其商业化面不在本产品范围。
- **All API Hub**：本地优先的"AI 资产管家"——聚合多站余额/用量/签到/价格对比/公告，
  一键分发客户端配置，远程管理 New API 系网关渠道。**不转发流量**，价值在"省事"。
- **MetAPI-Go**：服务端聚合网关——真实转发 + 智能路由（权重/冷却/熔断/重试）+ 多平台
  账号聚合 + 运维审计。三者中唯一做真实流量转发的，价值在"可用性与省钱"。

## 核心结论

**MetAPI-Go 在"转发 + 路由 + 运维"三角已形成差异化；客户端导出、首次接入向导、
测试台真值与路由成本真值已经补齐。商业化与多租户明确不做。**

三条关键用户动线：

1. **接入动线**：客户端导出与站点→账号→路由向导已串联平台识别、凭证、连通性测试
   和 token 路由；深链参数一次性消费，避免重复打开。
2. **巡检动线**：告警、每日摘要和首页今日快照已形成主动巡检入口。
3. **故障动线**：富化告警 → observability → fix-candidates 已形成带上下文的处理闭环。

## 产品方向

- **现在**：保持已交付能力的 CI、a11y、双数据库和发布门禁；不在没有证据前增加
  新的编排层。
- **operator-gated**：真实多通道 cascade、Codex/AnyRouter 探针（#558）。
- **需求驱动**：WebDAV 加密同步、移动端 PWA、Realtime transport。

执行状态只在 [`progress/MASTER.md`](progress/MASTER.md) 维护，避免对标文档成为第二份 backlog。

## 明确不做（定位边界）

- 多租户计费 / 钱包 / 订阅 / 支付——组合优于重造，真需要时前置 New API 实例
  （MetAPI-Go 本来就是它的上游聚合器）。
- 社交 OAuth 登录。
- 多实例 sticky 共享改造（当前诚实标注 single-instance）。
